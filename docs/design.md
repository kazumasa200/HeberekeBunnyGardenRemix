# 設計メモ

もとの知見は 別のメモ（`unity-rtx-remix-notes.md`）（RTX Remix for Minecraft のフォークを作った経験を Unity に当てはめたもの）。

## 問題

へべれけばにーがーでん（Unity 6000.0.31f1、Mono、URP）を RTX Remix で描きたい。ゲームは D3D11 で動いている。2026-11-09 に `-force-vulkan` と `-force-glcore` で起動を試したところ、どちらも「ビルドに含まれていない」で初期化に失敗した。D3D9 の横取りは使えないので、BepInEx のプラグインから Remix API（`remixapi_*`）でメッシュ・素材・カメラを直接渡す。

ランタイムは Remix Plus v2.0.0（API 1.0.0、<https://github.com/RemixProjGroup/dxvk-remix>）の「D3D11 のホストの道」を使う。最初は RTX Remix for Minecraft のランタイム（API 0.16.1）の `Startup` と子ウィンドウで組んだが、画面が真っ黒のまま進まなかったので乗り換えた（2026-11-09）。

守る制約は次のとおり。

- ゲームの D3D11 そのものが Remix の DXVK の上で動いていること。`.trex` の中身と、転送用の `d3d11.dll` / `dxgi.dll`（`native/forwarders`）をゲームの exe の隣に置く。転送用の DLL は配布物に入っていないので、Remix Plus のソースと同じものを自分でビルドする
- `remixapi_RegisterD3D11Device` は 1 回だけ、Unity の描画スレッドで呼ぶ。そのあとの Remix の呼び出しも、全部描画スレッドで行う（Remix はゲームの immediate context にコマンドを積む）
- `RenderD3D11` の描き先は、同じデバイスの MSAA 無しのレンダーテクスチャ。フレームはゲーム自身の `Present` で締まる。`Startup` と `Present` は呼ばない
- 素材・メッシュ・光源は `hash` がそのまま取っ手になる。0 は使えない（`INVALID_ARGUMENTS` になる）
- Unity は左手系で Y が上。Remix の既定は右手系で Y が上

## 使い方（呼ぶ側から見た形）

```csharp
// 起動（Plugin.Awake、メインスレッド）
var api = RemixApi.Load(Paths.GameRootPath);   // ゲームのフォルダの d3d9.dll から関数表を受け取る。構造体の写しの自己チェックもここ
gameObject.AddComponent<SceneMirror>().Init(api, log);

// 場面に入って 3 秒後（SceneMirror.Update、メインスレッド）: 形・素材・光源・空を「仕事」にして積む
geometry.Rebuild(scene); skinned.Rebuild(gen); SkyCapture.Capture(...);
// そのあと 1 秒ごと: あとから出てきた Renderer と、点いた・消えた・変わった Light（geometry.TrackLights）
// 毎フレーム: 動いた物・消えた物・LOD で描かれなくなった物（geometry.TrackChanges(camera)）

// 毎フレーム、URP のカメラの中（RemixCompositePass、ポストプロセスの前）
//   霧の濃さを測る → 環境だけの深さを描く → cmd.IssuePluginEvent（ここから描画スレッド）
//   → Remix の絵（HDR）をカメラの色に写す → ゲーム自身に、印の付いた不透明（キャラクターなど）と半透明を全部描き直させる
// 描画スレッド（SceneMirror.RenderFrame）
api.SetupCamera(pose);                           // カメラの行列そのもの（投影のずれも含む）
foreach (var l in lights) api.DrawLight(l);
api.DrawRetainedInstances(null);                 // 静的な物は置きっぱなしの実体（ゲームが描き直す物は影だけの印）
api.DrawInstance(character, toWorld, true, CategoryShadowOnly); // キャラクターは毎フレーム、影だけ
api.RenderD3D11(target);                         // 8 ビットの描き先（露出 -2）。フレームはゲームの Present で締まる（PresentHook）
resolve.Apply(target, hdr, fogFactor, fogColor, 4); // ×4 でゲームの尺度の HDR に戻し、ゲームの霧を混ぜる
```

## 形

- **`Remix/RemixApi.cs`**: Remix との境界のすべて。読み込み、関数表と名前で引く関数（`remixapi_RegisterD3D11Device`、`remixapi_RenderD3D11`）、構造体の写し、`sType` と `pNext` の詰め方、エラーコードを例外にすること、座標系の設定、Unity の行列から Remix の 3x4 への並べ替え。外からは Unity の型（`Matrix4x4`、配列）と `CameraPose` で呼ぶ。構造体の写しは private で、外からは見えない（per boundary-discipline）
- **`SceneMirror.cs`**: Unity の場面を Remix に映す役。メインスレッドでカメラとメッシュを写し取り、描画スレッドへ合図を出す。描画スレッドの側で Remix を呼ぶ。描き先のレンダーテクスチャも持つ
- **`RemixCompositePass.cs`**: URP のパス（不透明のあと、空とデカールの前）。霧の濃さ・環境だけの深さを描き、Remix の HDR をカメラの色に写し、ゲームが描き直す不透明（`OverlayBit` の印）を描かせる。空・デカール・半透明はそのあとゲーム自身が描く
- **`BakedLamps.cs` / `BakedLamps.Bvh.cs`**: 焼き込みにだけある明かりを Remix の光源に戻す。ライトマップから空の光を測り、照明の器具・木の根元に点光源とスポットライトを置き、残る明るさは補助光で埋める。器具の無い看板はライトマップの明るさで光らせ、木の葉は暗さを合わせる
- **`Remix/RemixResolve.cs`**: 描画スレッドの D3D11 の小さなシェーダー。Remix の 8 ビットの絵を ×4 の HDR に戻し、霧を混ぜる
- **`SceneGeometry.cs` / `SkinnedGeometry.cs` / `MaterialLibrary.cs`**: 静的な物・キャラクター・素材を、GPU から読み戻して Remix の仕事にする。Unity の素材の決まり（URP Lit のディテール、DXT5nm、なめらかさ、HDR の発光の色）を Remix の素材に直すのは `MaterialLibrary`
- **`StableId.cs`**: メッシュ・素材・テクスチャの hash を、名前と中身から作る（起動のたびに同じ値。RTX Remix Toolkit の置き換えが当たるように）
- **`Timing.cs`**: メインスレッドの処理の所要時間を名前ごとに足し込み、1 秒に 100 ms を超えたらログに書く（読み込みで固まる所を探す）
- **`DebugJump.cs` / `Picker.cs`**: 開発用（ステージへ飛ぶ、瞬間移動、会話のオート、ボタンを押したことにする、調べもの）
- **`Plugin.cs`**: BepInEx の入口と設定
- **`native/forwarders/`**: `d3d11.dll` / `dxgi.dll`。中身はエクスポートを `d3d9.<名前>` に転送するだけ（Remix Plus のソースのまま）
- **`tools/remix-layout/`**: 本物のヘッダーで、構造体の大きさとフィールドの位置、関数表の番号、`StructType` の値を出すプローブ。`RemixApi.Layout.Check` と `StructType` と `Slot*` は、ここで出した値と一致させる。ヘッダーを差し替えたら必ず回す

## まとめ方の判断

形の違う 2 案を比べた。

- **案 1（採用）**: C# から関数表を直接呼ぶ。DLL は 1 つで済み、C++ のビルドも要らない
- **案 2**: C++ の DLL を挟み、ゲームの都合に合わせた粗い関数（「カメラと実体の一覧で 1 フレーム描け」）を書き出す

案 2 で得られると考えたものは、3 つとも実際には得られないか、要らなかった。

- クラッシュからの保護: マイクラ版の `remixCall` も、例外を握りつぶさずに記録を書くだけだった。C++ を挟んでも、Remix の中で落ちればゲームは落ちる
- 呼び出しの回数を減らすこと: 置きっぱなしの実体（`SceneInstanceAdd`）を使えば、変わった物だけを呼べばよいので、もともと多くならない
- 構造体の二重定義をなくすこと: 案 2 でも、C# と C++ の間の受け渡し用の構造体を、両方に書くことになる。案 1 の写しには NVIDIA のヘッダーという正本がある

## 受け入れた代わりのもの

- 構造体を手で写す。その代わりに、プローブと読み込み時の自己チェックで、写し間違いを起動の時点で止める（2026-11-09 に、関数表の取りこぼしを実際にこれで見つけた）
- 描画スレッドへは、C# の関数を `GL.IssuePluginEvent` で直接呼ばせる（C++ の DLL を挟まない）。Mono が描画スレッドを自動でつなぐのに頼っている
- 最初の到達点では、Unity も同じ場面を描き続け（GPU を二重に使う）、Remix の絵で上から塗りつぶす。UI も消える。UI は `DrawScreenOverlayD3D11` で重ねる予定

## ほかの案

- 案 2（C++ の DLL を挟む）: 上のとおり
- RTX Remix for Minecraft のランタイム（0.16.1）と `Startup` の子ウィンドウ: 最初に試した。画面が黒いまま、原因（光源が無かったせいか）を詰める前に Remix Plus へ移った
- Remix の注入（D3D9 の横取り）: Unity 6 に D3D9 が無いので、使えない

## 実装で変えたこと

- 2026-11-09: ランタイムを Remix Plus v2.0.0 に替え、`Startup`/`Submit`/`Present` と子ウィンドウをやめて、D3D11 のホストの道（`RegisterD3D11Device`/`RenderD3D11`）にした。Remix の呼び出しを描画スレッドへ移した
- 2026-11-09: 素材・メッシュ・光源に、呼ぶ側が 0 以外の `hash` を渡すようにした（Remix Plus では hash が取っ手。0 だと `CreateMaterial` が 3 で失敗した）
- 2026-11-09: Remix の絵を画面へ写すのを、フレームの終わりの `Graphics.Blit` から、URP のカメラに積むパス（`RemixCompositePass`、`AfterRendering`）に移した。Unity 6 の URP は Screen Space - Overlay の UI をカメラの中（最後のコピーのあと）で描くので、その前に写せば UI が上に乗る。`SupportedRenderingFeatures.rendersUIOverlay` を倒す案は、URP が毎フレーム立て直すうえ、倒すと画面が真っ黒になったのでやめた
- 2026-11-09: カメラは `Camera.main` ではなく「画面向けの透視投影でいちばん手前のもの」を使う。キャラ選択は、背景の絵の平行投影カメラ（Base）の上に 3D のカメラ（Overlay）が重なっている。パスは重なりの最後の 1 台（`resolveFinalTarget`）でだけ動く
- 2026-11-09: 修正 Mod との同時導入: Remix で描く間は URP の MSAA を 1 にする（修正 Mod は 8x にする）。F8 で切ると元に戻す。解像度とフレームレートは修正 Mod のまま

- 2026-11-09: **フレームの締め**。Remix は Present のとき「最後に `RenderD3D11` で渡された先がスワップチェーンのバッファ」のときだけフレームを締め、フレームの番号を進める（`d3d11_swapchain.cpp` の `FinishRemixFrame`）。締めないと 2 フレーム目から描かれず、最初の 1 枚が残り続けた。Unity は中間のテクスチャ（`R8G8B8A8_TYPELESS`）に描いて Present の直前にスワップチェーンへ写すので、本物のバッファは Present の中でしか分からない。そこで `IDXGISwapChain::Present`/`Present1` を vtable で差し替え（`PresentHook`、使い捨てのスワップチェーンで vtable の場所を知る）、直前に `RenderD3D11(GetBuffer(0), render = false)` で締め先を渡す
- 2026-11-09: 場面の静的なメッシュ（`SceneGeometry`）とキャラクター（`SkinnedGeometry`）は GPU から読み戻す。静的な物は置きっぱなしの実体で、静的バッチされた物はまとめたメッシュ（ワールド座標）のその Renderer の分のサブメッシュを使う。動く物は毎フレーム変わった物だけ `UpdateRetainedInstances`。キャラクターは毎フレーム `SkinnedMeshRenderer.GetVertexBuffer` を読み戻し、2 回目からは同じ hash で `MeshInfoRefreshGeometryEXT`（形だけ差し替え、動きのベクトルとデノイザーの履歴が続く）
- 2026-11-09: スキニングのあとの頂点は **ルートボーンの座標**（無ければ自分の座標）。`Renderer.bounds` で決めようとしたが、このゲームはキャラの箱を 10000 m にしている（カリングよけ）ので使えなかった。ワールドだと思って渡すと、ADV で寝て、ステージでは原点に置かれて見えなかった
- 2026-11-09: テクスチャは `PrepareD3D11TextureEx`/`ImportD3D11TextureEx` で GPU のまま取り込み、素材からは「0x<hash>」の名前で指す。UV は反転しない（Unity は D3D11 のテクスチャを同じ UV で引けるように置いている）。Unity Toon Shader は `_BaseMap` が空で `_MainTex` に絵があるので、空でない最初のものを使う。`_BaseColor` は `MaterialInfoOpaqueAlbedoTintEXT` でテクスチャに掛ける。発光は URP の `_EMISSION`（`_EmissionColor` × `_EmissionMap`）。切り抜き（`_ALPHATEST_ON` か描く順番 2450 から）は `alphaTestType = 6`
- 2026-11-09: 光源の単位。URP は π を強さに含めるので、平行光源は Remix の値 = 色 × 強さ（Remix は 放射輝度 / sin²(半角) で使う）、点・スポットは半径 r の球で L = 強さ / r²。中身が同じ光源を消して作り直すと、Remix の後回しの消去で新しい方まで消えるので、作り直すのは強さが変わった物だけ
- 2026-11-09: **夜の見た目**。Remix の自動露出が夜を昼の明るさまで持ち上げていた（露出を下げて測ると、もともと夜の明るさだった）。自動露出を切って露出 -2 に決め打ち、Remix の絵はゲームのポストプロセスの前に写す（このゲームの紫は色調補正で付いている）。空は NUMOS で、太陽は地平線の下、本物の月は出さない（`rtx.conf`）
- 2026-11-09: Remix の開発メニューの入力用の窓は、キーボードの raw input を `RIDEV_NOLEGACY` で横取りし、ゲームのキーが効かなくなる（コントローラーだけ効く）。`rtx.useNewGuiInputMethod = False` で作らせない（`rtx.conf`、実行中は変えられない）

- 2026-11-10: **空**。ゲームの空（Skybox）を空だけのカメラで立方体に描かせ、緯度経度の DDS にしてドームライトにする（`SkyCapture`）。読み戻した面の行は D3D の並び（上の行が先）で、上下を返すと横の 4 面の雲が地平線の下に出た。Remix Plus はドームライトがあると、外れた視線に空を 2 回足す（`geometry_resolver.slangh` の外れの処理と `composite.comp.slang` の `applySkyContribution`）ので、明るさは 0.5 にした（見える空がゲームと同じになった。照らす光も半分になる）
- 2026-11-10: **LOD**。LODGroup の粗い段（LOD1 から）にだけある Renderer は渡さない。全部渡すと粗い形が細かい形に重なり、看板が壁に埋もれ、低い解像度の絵が上に出ていた（Stage01 で Renderer が 3962 個から 1872 個になった）
- 2026-11-10: **明るさの合わせ方**。ゲームの絵をポストプロセスの前の HDR のまま保存し（`mod.hdrdump`）、Remix の絵（ポストプロセスの後に写すと `sRGB(放射輝度 / 4)`）と同じ場所で比べる。仮の太陽（強さ 4、最初の頃の切り分け用）が消されずに残っていて、それまでの合わせはそれに狂わされていた。外したあと、3 つの視点で画面の平均がゲームとほぼ同じになった
- 2026-11-10: **環境光**。ゲームのシェーダーが使う値（`RenderSettings.ambientProbe`、線形）を上・横・下で測り、全体の分（直径 179° の上下 2 つ）と、空と地面の分（同じ細さの円錐）の 4 つの平行光源で近づける。`ambientSkyColor` は sRGB の値で、そのまま使うと緑が 6 倍ほど強かった
- 2026-11-10: **面光源**。Unity の面光源は forward の側に光る（逆にすると、通りの看板を照らす光が看板の方を向き、ゲームでは暗い看板が明るくなった）。範囲 1 m 以下の面光源は作らない（Unity の焼き込みは範囲の外を照らさないが、Remix の光には範囲が無い。自動販売機は範囲 20 m と 1 m の 2 つを重ねている）
- 2026-11-10: **店の中**。コンビニの中は焼いたあとで消した光でだけ照らされていて（場面に光源が無い）、明るさはライトプローブにしか残っていない（店の中の物は `lightmapIndex 65534`、プローブで照らされる）。天井の照明器具（素材の名前に Ceilinglight）に下向きの面光源を置き、真下の床（当たり判定で探す、トリガーは外す）で、近くの器具の光を足した照度がプローブの上向きの値 × π になる強さにする。細い器具だけでは元の光ほど壁や棚に回らないので、店の中で HDR を比べて 2 倍にした
- 2026-11-10: **霧**。Remix の API には霧を渡す口が無く、Remix の体積の霧は光を散らす物でゲームの霧の色にならない（遠くが暗くなるだけだった）。ゲームの URP の Unlit で、黒い素材と白い霧の色で場面を描くと `1 - f`（Unity の霧の式そのもの）が出るので、それを別の絵に描き、描画スレッドで D3D11 の小さなシェーダー（`FogBlend`、`d3dcompiler_47` でその場で作る）で `霧の色 × (1 - f) + 絵 × f` を混ぜる。Unity に入っているシェーダーだけでは、この混ぜ方ができなかった（`1 - f` をアルファに入れる道が無い）
- 2026-11-10: **半透明**。加算（URP の `_Blend 2`、シェーダーグラフの光の演出）は Remix の `kAlphaEmissive` で、発光の色と絵を Unity の色と絵にする（発光が無いと透けるだけで見えなかった）。URP の Lit の透明なガラス（`_Surface 1` で名前に glass）は Remix の透過の素材。光の筋（Volumetric Light Beam の `VolumetricLightBeamSD`、DontSave の子で `FindObjectsByType` に出てこない）は、同じ形の円錐を作り、VLB と同じ距離の減り方を発光の絵に焼く。パーティクルは毎フレーム `BakeMesh`（位置と回転まで焼く）で新しいメッシュにする。発光の色の定数は sRGB として読まれるので、線形の色を戻して渡す
- 2026-11-10: **服の切り替え**。服が破れる演出は、部品の出し入れ（`SetActive` と `enabled`）と素材の入れ替え（`sharedMaterials`）。見えている部品だけを描き、素材が変わったら次の形から新しい素材を使う。`mod.torn` でゲームの `Chara.ChangeTorn` を呼んで確かめた
- 2026-11-10: **キャラクター**。Universal Toon Shader の透明モード（`_TransparentEnabled`、頬の赤み・髪の先）は半透明にする（切り抜きにすると、髪の影が目の上に濃い帯になった）。髪が顔に落とす影を描いた「影の層」（素材の名前に `_shadow`）は、Remix が本当の影を出すので渡さない。UTS は暗い所でも主光源の色を下限に平らに明るく塗るので、トゥーンの素材に「影の色の絵（`_1st_ShadeMap` × `_1st_ShadeColor`）× 0.3」の発光を足す（`mod.toonglow`。夜のキャラクターはほとんど影の側。地の絵で光らせると髪が薄茶色になった）。ゲームではキャラクターに当たらない焼き込み専用の月明かり（赤・緑・青、合わせて 0.75）が Remix では当たるので、トゥーンの地の色は線形で 0.5 倍にする（`mod.toonalbedo`）。MatCap（金色の映り込み）は、マスク × MatCap の円の平均（中心ほど重く）× 主光源の色を、発光の絵に焼き足す
- 2026-11-10: **カメラ**。視野角と縦横比（`CameraInfoParameterizedEXT`）ではなく、Unity の行列そのものを渡す（左手系のビューと D3D の投影に直す）

- 植え込み（`M_leaves_tree 4`、表だけ描く切り抜き）は、葉どうしの陰でゲームより暗い
- 走っている車（`ObjCar_MM`）が、照明のそばを通るときに Remix だけ強く光って見えることがある（Stage06 で 1 回見た。原因は未確認）
- カメラが物の中に入ると、ゲームは裏の面を描かないので外が見えるが、Remix は真っ黒になる（Stage06 のトラックの荷台の中のパンツの位置で確かめた。ふつうの遊び方のカメラでは未確認）
- 金属の反射は弱めてあるだけで、真上の環境光はまだ少し映る（マンホールの真ん中がゲームより青い）
- 衣装（金のバニースーツ）は反射しない（上の「衣装の映り込みは見送り」）
- 金属の多い素材（車の塗装 `_Metallic 0.5`、金属の地図を持たない物）は、Remix では周りが本当に映り、ゲームより青く冷たく見える
- RTX Remix Toolkit での編集: Remix Plus 2.0.0 は、API で渡したメッシュにも置き換え（`mod.usda`）を引く（`SceneManager::submitExternalDraw` がメッシュの hash で `getReplacementsForMesh` を引く）し、キャプチャにも入る（`rtx_game_capturer.cpp`）。メッシュと素材の hash は起動のたびに同じにした（上の `StableId`）。まだ確かめていないこと: 実際に Toolkit でキャプチャを開いて置き換えを作り、次の起動で当たるか。素材だけの置き換え（メッシュはそのまま）が API の素材に効くか。光源は API の光源（external light）で、置き換えの対象にならない見込み（光源を編集するなら、この Mod の側に上書きのファイルを作る方が確か）
- ゲームの更新などで、名前も頂点の数も同じまま中身だけ変わったメッシュや絵は、同じ hash になる（Toolkit の置き換えは当たり続ける）。素材は、欄の値が 1 つでも変わると hash が変わる（置き換えが外れる）
- 衣装選択の部屋はゲームより暗い（上の「無効にして置いてある焼き込みの照明」）
- 道路は、ディテールを前に出すため、地の絵の大きな模様は平均の色になっている（Remix の素材は UV が 1 つ）。粗さだけは升目ごとに地の UV の物を使う（升目の境目で、粗さの絵の端がわずかに混ざる）
- 濡れた所は、ゲームより鏡に近い（Remix では水の膜）。ゲームの濡れた所の赤っぽい照り返し（反射プローブ）は出ない。ハイライトの影は、ゲームのシャドウマップの影（Remix の影ではない）。Remix 自身の平行光源のハイライトも少し足される（描き足しと二重）
- 道路のハイライトの描き足しは、道路の素材（ディテールが細かく、金属の絵を持つ URP Lit）だけ。歩道のタイルなど、ほかのなめらかな面のハイライトは Remix まかせ（ゲームより弱い）。Stage02〜09 では見ていない（素材が 4 種類を超えると、5 種類目からは描き足さない）
- キャラクターが光る素材になったので、近くの壁や床をわずかに照らすはず。離れた所からは差が見えなかったが、足元の近くでは確かめていない
- 読み込みのとき、Remix の記録にいちばん長いフレーム 2.7 秒が残る（Mod のメインスレッドの仕事は 1 秒あたり 0.3 秒ほどで、その中には無い。ゲーム自身の場面の読み込みか、Remix の側かは切り分けていない）
- 面光源の範囲（Unity の焼き込みの範囲の外）は、範囲 1 m 以下の物を作らないだけ。高い所の大きな空の板（範囲 30 m）は通りまで照らしている
- 毎フレームのキャラクターの読み戻しは CPU で組み立てている
- Stage02〜09 は、道順に沿った HDR の比較（7〜12 視点）で確かめた。ミニゲーム・ADV・キャラ選択を見たのは Stage01 だけ（今回の空と補助光の変更のあとは見直していない。照明も看板も無い場面では、空を測る処理は動かない）
- 配るときは、Remix Plus の `.trex` の中身（約 880 MB）、転送用の DLL、`rtx.conf` をゲームのフォルダに置いてもらう

## 次に作るもの

ミニゲーム・ADV・キャラ選択を、今の環境光で見直す。木の葉を頂点カラーで板ごとに合わせる。植え込みの暗さ。

開発の道具:
- F8: Remix とゲームの絵を切り替える。Ctrl+F8: ADV を飛ばして Stage01 に入る。F7: 場面の中身をログに書く
- `tools/restart.sh [Stage01]`: ゲームを閉じて DLL を入れ替え、Steam から起動する。ステージ名を付けるとタイトルからそのまま入る
- `tools/shot.sh`: ゲームの中から画面を保存させる（外から撮ると、全画面の具合で黒く写ることがあった）。`capture.req` に「枚数, 間隔（秒）」を書くと続けて撮る。`tools/compare.sh 出力.jpg`: Remix とゲームの絵を上下に並べる
- `tools/tour.sh 名前 出力フォルダ [視点の数]`: ステージの道順（`mod.waypoints`）に沿ってカメラを置き、視点ごとにゲームと Remix の HDR を書かせて、並べた画像（Remix | ゲーム | 比の色分け）と数字を出す。`tools/lmmap.py`: `mod.lmmap` が書いた地面のライトマップの地図を画像にする
- `tools/variants.sh 出力.jpg "x,y,w,h" '設定;設定' ...`: 設定の組ごとに撮って、同じ切り抜きを並べる。`tools/hdrvariants.sh "x0 x1 y0 y1" 'タグ:設定;設定' ...` と `tools/hdrstat.py`: 設定の組ごとに HDR を書かせ、範囲の平均と輝度の p10 / p50 / p90 / p99（明るい側と暗い側の差 = 質感）を出す。`tools/hdrview.py`: 同じフレームのゲームと Remix の HDR を左右に並べる
- `tools/deskburst.py 出力.jpg x y w h [枚数] [間隔]`: 画面そのものを続けて撮って並べる（ゲームを通さない。フレームごとのちらつきは、これでしか見えなかった）。`tools/blushcount.py x y w h`: その範囲の赤さを続けて測る。`tools/deskdiff.py`: 赤さの違う 2 フレームの差を画像にする。どれも `capture_hdr.py`（置き場所は `tools/local.env` の `HBG_CAPTURE_DIR`） を使う
- `tools/remixconf.sh '設定 = 値' ...`: 動いているゲームの Remix に設定を送る（`rtx.` はそのまま Remix へ）。`mod.` で始まるものはこの Mod の切り替え:
  - 絵: `mod.remix`、`mod.fog`、`mod.cam`（「x, y, z, 左右, 上下」で固定、`off`、`log`）、`mod.torn`
  - 進める: `mod.stage`（「Stage01」、「Stage01,Normal,adv」で始まりの ADV から）、`mod.scene`（`CharaSelection` / `OutfitSelection` / `StageSelection` / `Title` など、ゲームの場面の切り替えを呼ぶ）、`mod.goto`（`pants` / `goal` / 「x, y, z」へ瞬間移動）、`mod.damage`（数か `torn`: ゲームのダメージの処理を呼ぶ。`torn` は服が破れる演出まで）、`mod.advauto`（会話をオートにし続ける）、`mod.press`（`A` などを 1 フレームだけ押したことにする。画面に鍵がかかっていても効く）
  - 明るさ: `mod.skyscale`、`mod.lightscale`、`mod.sunscale`、`mod.ambientscale`、`mod.areascale`、`mod.rectflip`、`mod.bakedlights`、`mod.skiplight`（名前の一部を | で区切る）、`mod.emissivescale`、`mod.roughmin`、`mod.metaltint`、`mod.wettint`（濡れた所の反射の色、すぐ効く）、`mod.wetsmooth`（濡れた所のなめらかさ、次に読む場面から）
  - 調べる: `mod.shaders`（場面のシェーダー・半透明の素材・デカール・映り込みの設定）、`mod.near`（「x, y, z, 半径」の Renderer）、`mod.matset`（「素材の名前の一部, _欄=数, +キーワード, -キーワード」: ゲームの素材そのものを書き換えて、ゲームの絵のどの項が効いているかを切り分ける）、`mod.lightint`（「Light の名前, 強さ」）、`mod.watch`（「名前の一部, フレーム数」: その Renderer が描き始めの瞬間に有効か）、`mod.timescale`、`mod.passtest`（1 = 合図を出さない、2 = パスを積まない、5 = Remix に描かせない、8 = 描かせる前の Flush をしない）、`mod.sunhighlight`、`mod.overlay`（0 でキャラクターの描き直しをやめる）、`mod.toonglow`、`mod.toonalbedo`、`mod.lodcull`、`mod.uvrange`（名前で選んだメッシュの UV の範囲。次に読む場面で）、`mod.overlaps`（箱が重なっている物の組）、`mod.cull`（裏の面を描かない指定。次に読む場面から）、`mod.showchara`（Remix が持つキャラクターを Remix の絵に出す）、`mod.dump`、`mod.pick`（画面の 1 点の物と素材、近い順に 12 個）、`mod.find`（名前で Renderer、Renderer ごとの上書きも）、`mod.matinfo`（名前で素材の全部の欄）、`mod.texprobe`（いちばん明るい画素も）、`mod.texdump`（「素材, 欄」の絵を PNG に）、`mod.lightsnear`（その辺りの光源とライトプローブ）、`mod.emissive`（光る素材の一覧）、`mod.hdrdump`（ゲームと Remix の HDR の絵。値を名前にするとファイル名に入る）、`mod.waypoints`（道順）、`mod.lmpick`（画面の 1 点のライトマップの値・空の予想・置いた光源の予想）、`mod.lmmap`（地面のライトマップを上から見た地図。値は高さの上限）、`mod.farfield`（次に読む場面で、照明から離れた面のライトマップを向きと高さごとに）、`mod.fills`・`mod.fillshare`（補助光。次に読む場面から）、`mod.lampcache`（照明の結果の保存と再利用。次に読む場面から）
